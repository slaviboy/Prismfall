# Blender asset pipeline

Every 3D model Prismfall ships is generated by a Python script that runs inside Blender in background mode. The exported GLB files are then optimised with glTF-Transform and copied into `content/`. The optimised outputs are committed, so building, testing and playing the game never need Blender or Python. You only need Blender to change a model.

## 1. Requirements

- **Blender 5.2 LTS.** `scripts/build-blender-assets.ts` runs the executable named by the `BLENDER_PATH` environment variable. Without it, the script uses the default Windows install path `C:/Program Files/Blender Foundation/Blender 5.2/blender.exe`. If neither exists it stops with `Blender not found at … Set BLENDER_PATH.` The helper module `common.py` targets Blender 5.x.
- **Node 22 or later and the dev dependencies.** The optimiser is `@gltf-transform/cli` 4.5.1, run from `node_modules/@gltf-transform/cli/bin/cli.js`.
- Preview renders use Cycles on the CPU; no GPU is required.

## 2. Running it

```
npm run assets:blender                      # every generator in pipeline.json
npm run assets:blender -- desert            # only generators whose script name contains "desert"
npm run assets:blender -- --no-preview      # skip the Cycles preview renders
npm run assets:blender -- flora --no-preview
```

The first argument that does not start with `--` filters generators by a substring of the script file name. `--no-preview` is passed through to the Python scripts.

For each generator in `assets/blender/pipeline.json`, the runner:

1. runs `blender -b --factory-startup --python-exit-code 1 --python assets/blender/scripts/<script> -- [--no-preview]` from the repo root (a Python error fails the run);
2. prints the script's `…_OK` summary line (for example `DESERT_OK 17 objects 48352 triangles`) and the elapsed time;
3. for each output mapping, optimises every `.glb` in the export folder into the content folder (section 8) and copies every `.json` unchanged. Other files are ignored.

The runner processes every GLB it finds in an export folder, so delete stale exports by hand when a script stops producing a file.

`smoke_test.py` is not in the pipeline. It checks that Blender can run headless and export a GLB:

```
blender -b --factory-startup --python assets/blender/scripts/smoke_test.py -- out.glb
```

It builds a bevelled cube, exports it and prints `SMOKE_OK <vertex count> verts -> out.glb`.

Models are shared between stages by absolute path. Northern Lights reuses `crystal_arch`, `rune_a` and `rune_c` from the ice kit, and The Abyss reuses `colonnade`, `gateway`, `monolith_0` and `monolith_1` from the desert kit, both through the `gltfScene` `include` filter. The flora kit and the creatures are used by most stages.

Conventions that the game relies on:

- **Object names are API.** `scatter` items name flora objects (`"mesh": "stone_lantern"`). `gltfScene` matches names for `include`, `rotate` (`^gear_`), `pistons` (`^piston_rod_`) and `snapRules`.
- **Origins sit at the object's base.** Kit objects are placed at their world (x, y) with the origin at z = 0, so `snapToGround` can rest each top-level object on the procedural terrain. Flora objects sit at the world origin so instances can be placed anywhere.
- **Coordinates.** Blender is Z-up, and the glTF export converts to Y-up: Blender +Y (depth) becomes three.js −Z, away from the camera. The playfield is at the origin.

## 5. Shared helpers (`common.py`)

| Helper | What it does |
|---|---|
| `reset_scene()` | Factory settings with an empty scene, metric units. |
| `make_material(name, color, metallic, roughness, emission, emission_strength)` | A Principled BSDF material. The name is what the game matches on (section 7). |
| `bake_dirty_vertex_ao(obj)` | Bakes Blender's Dirty Vertex Colors into a byte colour attribute named `AO` (face-corner domain) and makes it active. With `vertex_colors=True` it is exported as `COLOR_0`. |
| `export_glb(objects, path, vertex_colors=False)` | Exports the selected objects as GLB: modifiers applied, Y-up, normals, UVs, materials, and the active colour attribute when `vertex_colors` is set. |
| `save_blend(path)` | Saves the generated scene as a compressed `.blend` in `assets/blender/source/`. |
| `write_metadata(path, data)` | Writes a JSON sidecar with LF line endings. |
| `render_preview(path, …)` | A small Cycles CPU render (960×540, 24 samples by default, two area lights) to `assets/blender/previews/`. The preview camera and lights are removed afterwards. |

`common.py` states that every generator is deterministic: running it again reproduces the same `.blend` and GLB.

### Vertex-colour AO

The environment kits (desert, flora, ice, japan) bake AO on every object. The foundry kit bakes it only on large structural pieces (`back_wall`, `gear_`, `column_`, `anvil_`, `crucible`, `floor_L`, `floor_R`, `catwalk`). Blocks and creatures carry no vertex colours. At runtime, the material remapper multiplies the base colour by `mix(0.35, 1, COLOR_0.r)` when the mesh has `COLOR_0` and the layer's `vertexAO` parameter is true (the default). Creases therefore darken to 35 % at most without any texture.

## 6. Creatures: metaballs, joint attributes and rigs

`creatures.py` builds each body in four steps:

1. **Body.** `build_metaballs` places metaball capsules (limbs, neck, tail) and ellipsoids (torso, hump, head, fins) along a stick-figure skeleton. It converts them to a mesh and applies a Smooth modifier (factor 0.5, 4 iterations). Resolution is 0.035 for the camel, 0.022 for the deer and 0.085 for the whale.
2. **Joint attributes.** Each vertex gets two float point attributes: `_JA` is the primary joint index and `_JB` is the parent joint index (−1 = none). Both come from the nearest skeleton segment. A knee vertex therefore carries the knee as `_JA` and the hip as `_JB`, so a two-bone chain bends correctly.
3. **Export.** The mesh is exported with `export_attributes=True` (custom attributes) and without UVs.
4. **Rig file.** `<name>.rig.json` lists the joints. Pivots and axes are converted from Blender Z-up to glTF Y-up as (x, z, −y).

The module docstring describes a skin-modifier body. A `build_skin` helper still exists, but all three creatures are built with `build_metaballs`.

The rig format is validated at runtime by `rigSchema` (`src/rendering/creatures/rig.ts`):

| Field | Meaning |
|---|---|
| `name` | Creature name. |
| `forward` | Facing axis: `-z` (default), `+z`, `-x`, `+x`. |
| `height` | Body height in metres. |
| `stride` | Ground distance covered by one gait cycle at scale 1. |
| `bob` | Vertical body bob amplitude (two lifts per cycle). |
| `sway` | Side-to-side roll amplitude in radians (default 0.025). |
| `joints[]` | Up to 16 joints: `name`, `pivot`, `axis`, `amp`, `phase`, `freq` (default 1), `bias` (default 0), `rectify` (−1..1; 0 swings both ways, ±1 bends only to one side, for knees and hocks). |

From `content/shared/creatures/camel.rig.json`:

```json
{
  "name": "camel",
  "forward": "-z",
  "height": 2.02,
  "stride": 1.15,
  "bob": 0.035,
  "joints": [
    { "name": "neck", "pivot": [0, 1.3, -0.62], "axis": [1, 0, 0], "amp": 0.07, "phase": 0.1, "freq": 2, "bias": 0.0, "rectify": 0 },
    { "name": "fl_hip", "pivot": [0.2, 1.22, -0.48], "axis": [1, 0, 0], "amp": 0.4, "phase": 0.0, "freq": 1, "bias": 0.0, "rectify": 0 },
    { "name": "fl_knee", "pivot": [0.2, 0.66, -0.52], "axis": [1, 0, 0], "amp": 0.75, "phase": 0.22, "freq": 1, "bias": 0.0, "rectify": -1 }
  ]
}
```

(The file has ten joints: neck, four hips, two knees, two hocks and a tail.)

The joint angle at gait phase `p` is `bias + amp × shaped(sin((p × freq + phase) × 2π)) × gait`. `rectify` blends the sine toward a half-wave curve that bends only in the direction of its sign (`jointAngle` in `rig.ts`, mirrored in the vertex shader). The `creatureHerd` component loads the rig with `ctx.assets.json(rig)` and the model with `ctx.assets.loadGLTF(model)`. It then bakes the mesh into rig space and animates every representation (surface particles, solid mesh) on the GPU. GLTFLoader lowercases custom attribute names, so `bakeCreatureGeometry` reads `_ja`/`_jb` as well as `_JA`/`_JB`.

The creature GLBs have no `.meta.json`. The rig file is their only sidecar.

## 7. Material names and in-game presets

Blender materials are placeholders. In game, the `gltfScene` and `scatter` components rebuild them as TSL node materials, following `materials` rules in `stage.json` (`src/rendering/environments/components/materialRemap.ts`):

```json
{ "match": "^hotMetal", "preset": "hot", "color": "#2a0a04", "emissive": "#ff7a2a", "emissiveIntensity": 0.85, "musicGlow": 0.8 }
```

(from the Ember Foundry `hall` layer)

| Rule field | Meaning |
|---|---|
| `match` | Regular expression, case-insensitive, tested against the Blender material name. The first matching rule wins. |
| `preset` | `darkMetal`, `metal`, `hot`, `emissive`, `glass`, `stone`, `foliage`, `ice` or `keep`. |
| `color` | Base colour. Without it, the Blender base colour is used (or `#808080`). |
| `emissive`, `emissiveIntensity` (default 1) | Emissive colour and strength. Without `emissive`, the material has no glow. |
| `roughness`, `metalness` | Override the preset values. |
| `musicGlow` (default 0.5) | How strongly the glow follows the music. |

| Preset | Roughness | Metalness | Node material |
|---|---|---|---|
| `darkMetal` | 0.45 | 0.9 | `MeshStandardNodeMaterial` |
| `metal` | 0.3 | 1 | `MeshStandardNodeMaterial` |
| `hot` | 0.6 | 0.4 | `MeshStandardNodeMaterial`; the emissive flickers slightly (±8 %) |
| `emissive` | 0.5 | 0.1 | `MeshStandardNodeMaterial` |
| `glass` | 0.05 | 0 | `MeshPhysicalNodeMaterial` with clearcoat 1, clearcoat roughness 0.08, no transmission |
| `stone` | 0.85 | 0 | `MeshStandardNodeMaterial` |
| `foliage` | 0.78 | 0 | `MeshStandardNodeMaterial` |
| `ice` | 0.08 | 0 | `MeshPhysicalNodeMaterial`, as `glass` |
| `keep` | (0.5) | (0) | The Blender material is left as exported, unless a vertex displacement (scatter sway) forces a rebuild |

Every rebuilt material:

- multiplies its colour by the vertex AO (section 5);
- gets the crossfade reveal mask: an alpha-tested front that spreads outward from the viewer as the world fades in;
- when `emissive` is set, glows with `emissive × emissiveIntensity × (1 + music × musicGlow) × <reactive "emissive"> × presence`. Here `music` is `0.6 × bass + 0.4 × beatPulse`. The glow is also written to the emissive render target that drives bloom.

Materials that match no rule are treated differently by the two components. `gltfScene` leaves them exactly as exported, with no reveal mask. `scatter` converts them with the `stone` preset.

The material names are the contract between the Blender scripts and `stage.json`. This is why the optimiser runs with `--palette false` (next section).

Example mappings from shipped stages:

| Stage layer | Rules |
|---|---|
| Ember Foundry `hall` | `^darkMetal` → `darkMetal`, `^steel` → `metal`, `^brass` → `metal`, `^hotMetal` → `hot`, `^furnaceGlow` → `emissive`, `^molten` → `emissive` |
| Frozen Kingdom `citadel` | `^iceWall` → `ice`, `^iceDeep` → `ice`, `^snowCap` → `stone`, `^iceGlow` → `emissive` |
| Ancient Garden `temple` | `^lacquer`, `^woodDark`, `^roofTile`, `^plaster` → `stone`; `^gold` → `metal`; `^lanternPaper` → `emissive` |
| Moving Sands `ruins` | `^sandstoneRed`, `^sandstone`, `^paleStone`, `^darkStone` → `stone`; `^glyphGlow` → `emissive` |
| Folded Sky `lantern-grove` | `^stone` → `stone`, `^lanternGlow` → `emissive`, `^blossom` → `foliage`, `^bark` → `stone` |

## 8. Optimisation

Each exported GLB goes through:

```
node node_modules/@gltf-transform/cli/bin/cli.js optimize <in.glb> <out.glb> \
  --compress meshopt --texture-compress webp \
  --simplify false --instance false --flatten false --join false --palette false
```

| Flag | Effect | Why |
|---|---|---|
| `--compress meshopt` | Reorders vertices, quantises attributes (`KHR_mesh_quantization`) and compresses buffers (`EXT_meshopt_compression`, level `high`). | Small files that decode quickly. |
| `--texture-compress webp` | Re-encodes textures as WebP. | No current kit uses image textures (the shipped GLBs contain no images), so this has no effect today. |
| `--simplify false` | No mesh decimation. | Keeps authored silhouettes and bevels. |
| `--instance false` | No `EXT_mesh_gpu_instancing`. | Each object stays its own named node. |
| `--flatten false` | Keeps the node hierarchy. | Top-level objects are snapped to the ground one by one, and `include` filters by top-level name. |
| `--join false` | Does not merge meshes. | Joining would lose the per-object names that `scatter`, `rotate`, `pistons` and `snapRules` use. |
| `--palette false` | Does not build palette textures or merge materials. | Palette merging replaces materials with merged palette materials, which strips the material names. The material remap rules then match nothing. |

The other default steps of `optimize` still run: `dedup`, `weld`, `resample`, `prune` and `sparse`. `prune` drops UV sets that no texture uses and colour sets other than `COLOR_0`, and keeps custom attributes. The shipped GLBs therefore keep `COLOR_0` (kits) and `_JA`/`_JB` (creatures), and carry no UVs. All shipped GLBs report the generator `glTF-Transform v4.5.1` and use `EXT_meshopt_compression` and `KHR_mesh_quantization`. The kits with glowing materials also use `KHR_materials_emissive_strength`.

### Quantisation and dequantisation

Observed in the shipped files (`camel.glb`, `flora.glb`):

| Attribute | Stored as |
|---|---|
| `POSITION` | normalised 16-bit integers (`SHORT`), with the dequantising scale and offset moved into the mesh node's transform |
| `NORMAL` | normalised 8-bit integers (`BYTE`) |
| `COLOR_0` | normalised 8-bit unsigned integers (`UNSIGNED_BYTE`), RGBA |
| `_JA`, `_JB` | 32-bit floats (not quantised) |

The runtime handles this in three ways:

- `AssetCache` (`src/rendering/assets/AssetCache.ts`) loads every GLB with three's `GLTFLoader` and the meshopt decoder. GLTFLoader marks quantised attributes as normalised, so three reads them as floats in −1..1 (or 0..1), and the node transform restores real units. Objects used in the scene graph as they are, as in `gltfScene`, need nothing else.
- Code that copies vertices out of a GLB must apply the node's world matrix itself. `bakeCreatureGeometry` (`src/rendering/creatures/surface.ts`) and the scatter `bakePart` both transform positions by `matrixWorld` and normals by its normal matrix. Their comments note that this transform is gltf-transform's dequantisation and must be kept, not inverted.
- Block designs are recentred and rescaled from their bounding box to the cell size (`normaliseBlockGeometry`). The uniform dequantisation transform does not matter for them.

## 9. Metadata files

Every kit writes a `*.meta.json` next to its GLB, and the runner copies it to `content/`. No game code reads these files; they document the asset.

| File | Fields |
|---|---|
| `blocks.meta.json` | `generator`, `unit` ("1 cell = 1 m"), `variants` (per design: `file`, `triangles`, `dimensions`) |
| `flora.meta.json` | `generator`, `objects` (names), `triangles` (per object), `materials`, `placement`, `license` |
| `desert.meta.json`, `foundry.meta.json` | `generator`, `objects` (count), `triangles` (total), `materials`, `license`; plus `placement` (desert) or `animated` (foundry: `gear_*` rotate, `piston_rod_*` pistons) |
| `ice.meta.json`, `japan.meta.json` | `generator`, `objects` (names), `triangles` (total), `materials`, `license` |

All kit metadata files carry `"license": "Original work for Prismfall"`. `blocks.meta.json` has no `license` field. Creatures have rig files instead of metadata.

`blocks.py` describes its designs as exactly 1×1×1, but `blocks.meta.json` records `faceted` at 1.14 and `pillow` at 1.011 on each axis. The game rescales every design to the cell size, so this has no visible effect.

## 10. Committed outputs

Commit everything the pipeline writes: the optimised GLBs and JSON in `content/`, the raw exports, the `.blend` sources and the previews in `assets/blender/`. The build and the game read only `content/`. `assets/blender/**` is excluded from ESLint and is not bundled.

After regenerating:

1. run `npm run content:validate`;
2. look at the affected stages in game (`npm run content:shots -- --stages <id>` after `npm run build:test`);
3. add any new files under `content/` to `ASSET_LICENSES.md`, or the asset-licence test fails.

## 11. Adding a kit

1. Write `assets/blender/scripts/<name>_kit.py` on top of `common.py`: `reset_scene()`, build the objects, `make_material()` with meaningful names, `bake_dirty_vertex_ao()`, `export_glb(objects, path, vertex_colors=True)`, `write_metadata()` with a `license`, `save_blend()`, `render_preview()` unless `--no-preview` is passed, then print a `<NAME>_OK` line.
2. Put each object's origin at its base so it can be snapped, and give objects stable names.
3. Add `{ "script": "<name>_kit.py", "outputs": [{ "from": "assets/blender/exports/<name>", "to": "content/stages/<id>/models" }] }` to `pipeline.json`.
4. Run `npm run assets:blender -- <name>`.
5. Reference the GLB from a `gltfScene` or `scatter` layer, with one `materials` rule per Blender material name.

`make_material`'s docstring calls Blender colours "previews only". That holds only when every rule sets `color`. A rule without `color`, and any material left unmatched in a `gltfScene`, uses the Blender colour in game. Also, `bake_dirty_vertex_ao` accepts a `strength` argument but does not use it, so the value `desert_kit.py` passes has no effect.
